I love AI. It's an amazing technology that, when used correctly, can really help engineers (and non-engineers!) build great tools and products. It democratized software in a way never seen before.

But that's exactly the problem. It's the midas touch of software. People build new features, products or tools with just a few prompts. Thousands and thousands of lines of code that nobody takes the time to understand. Why would you, the AI understands it, no? And this is true to a certain extent but at some point this breaks. The AI starts making mistakes, tacking on features in random places, making each and every change harder and harder. And then... Something is breaks! But who's to blame? Computers famously [can never be held accountable](https://simonwillison.net/2025/Feb/3/a-computer-can-never-be-held-accountable/) so not the AI tool. Okay, the developer then? Well yes.

But what do we see happening next? Will they decide to take things slower, read the actual output, try to understand what is going on, stick to engineering best practices?

![meme](/images/blog/just-one-more-ai-tool/meme.jpg)

No of course not. This can all be solved with just another AI tool! A back and forth chat not fast enough? Lets use agents! Agents producing bad code? Just have agents check the agents! Pull requests longer than War & Peace? Just have AI review the AI generated code! Do some user testing? No need there is an AI tool for this!

It's [already known](https://medium.com/devops-ai/ai-makes-big-tech-engineering-practices-a-small-team-problem-0d0b432af53b) that AI can be an accelerator for teams who stick to good engineering practices and spend time building strong foundations. And this of course makes a lot of sense. AI can't actually _think_ and is definitly not good at saying no, so you have to make it follow the pattern you want it to. You can have many `.md` files full of rules, and this will get you a long way, but the absolute best way to do this is to have a good foundation in the first place. No need to tack a feature on behind some if statements in a codebase when it's obvious where the feature should go. No more huge pull requests if code is modular and reusable in the first place.

So if you are thinking about that cool new AI tool you saw in a CTO LinkedIn post or sponsored talk at a conference, maybe ask yourself first

> Do I really need this Formula 1 engine while the wheels are flat? Or should I finish a lap first before trying to accelerate?
